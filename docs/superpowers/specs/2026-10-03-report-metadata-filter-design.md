# 第二批A：发布日期、发布机构与可信查询过滤

## 目标和边界

消除已经复现的“正确报告因错误元数据/自动硬过滤在向量检索之前被排除”。本批先完成元数据与过滤修复，再评估是否进入候选排序的独立批次。

## 已复现的根因

1. `resolve_document_date()`优先使用`parsed.path.name`，实际为上传临时UUID；年份正则允许从字母包围的数字匹配年份。同一通号正文，在`.abcdefabcdefabcdefabcdefabcdefab.uploading.pdf`下得到2026-09-27，在含`2053`/`2006`的临时名称下分别得到2053-01-01/2006-01-01。真实标题/原文件身份并未改变，日期却受随机UUID影响。
2. 正文扫描前3000字符，首个“报告期”也被当成发布日期。`报告期：2026年6月30日。发布日期：2026年9月24日。`返回2026-06-30；缺失发布日期会用文件mtime，国机汽车因此存成入库日2026-10-02，而原PDF封面为2026-09-24。
3. 发布机构不可信：通号原PDF第一页页脚为“东吴证券研究所”，当前标量为“中信证券”；杰瑞PDF第一页同样为东吴证券，当前标量为空。国机汽车机构太平洋证券正确，但日期错误。日期与机构需要一并治理，单修日期无法恢复前两份报告。
4. LLM推断与API显式条件无来源区别，都转成硬过滤；`if not filters`也把显式空字典当作未传入。dense空召回兜底仍沿用完全相同过滤，不解决错误过滤。日期校验只检查字符串形状，`2026-02-31`也被接受。
5. 当前知识库指纹已经包括date/broker等检索标量：修改元数据会改变KB指纹，必须按已有门禁留存版本，不可宣称“向量未变，所以可以跨库显著性比较”。

## 方案选择

- A：仅修抽取并更正18份报告的元数据。范围最小，但自动推断的财务期间和无依据的机构/类别条件仍可能造成漏召。
- B（推荐）：可信元数据修复 + 过滤来源/证据分离 + 仅对未经确认的自动条件做有界兜底。同时治理入库与查询边界，保留用户明确限制，能够逐阶段验收。
- C：默认取消所有自动元数据过滤。可作为诊断对照，不能作为默认修复；会失去报告范围约束并增加跨公司、跨期间污染。

以下为方案B的具体设计。

## 1. 文档日期与发布机构

建立独立、可测试的文档公共元数据解析器，输入原始source、原PDF封面/页脚的页码和位置、PDF内置标题、解析正文以及显式metadata，输出日期/机构候选及审计证据。不以临时上传路径作为业务身份。

- 现有业务/API/Milvus列`date`保留，语义固定为“报告发布日期”；本批不改名、不新增Milvus列。`ingested_at`继续表示入库时间，不回填到date。
- 优先接受经过真实日历验证的显式发布日期；自动识别依赖封面/报告日期标签、独立封面日期位置，以及具备明确发布语义的原文件名或内置标题。若可靠来源冲突，不任意取第一个候选，标记需复核。
- 财务报告期、统计期、相关研究日期、走势图刻度、表格年份不作为发布日期。只出现年份或年月，不擅自补01-01/01制造精确日。超出合理发布范围的自动候选进入复核，不改用mtime。
- 原PDF有日期但MinerU正文排列靠后时，用PDF第一页的文本位置恢复，不通过扩大全文扫描去抓任意历史日期。无法确认则date为空并记录原因，不拒绝正文入库，不伪造发布日期。
- 发布机构依赖自身封面/页脚/署名证据；PDF内置标题和原文件名可作辅助，但不盲信正文中被引用的券商。机构别名只能通过受控映射归一化；无可靠归属或冲突则留空待审核，不猜测。
- 抽取规则版本、候选、来源、PDF SHA、页码、原文位置、冲突/弃用理由保存到审计产物。自动审核仍为silver，不声称人工批准。
- 保持已有report_type判别payload约束；date/broker等公共字段与业务类型校验协同，日期复核原因不因业务元数据通过或人工局部PATCH而无声消失。

## 2. 查询过滤边界

引入可审计的过滤计划：显式API条件、自动候选、已确认自动条件、未确认提示、最终有效条件、被拒绝条件及原因。实际检索及每次兜底都记录所用过滤，而不是只输出第一次推断结果。

- `filters is None`才表示未提交；显式`{}`表示不使用过滤，不自动重新推断；`infer_filters=false`按既有契约禁用推断。
- 显式API条件始终为硬约束，不由空召回自动删除。非法日期、反向范围、非法字段/行业组合等明确返回4xx，不静默缩小/取消用户条件后跨范围检索。防注入、租户/版本/删除状态边界不变。
- LLM输出为不可信候选：要求依据原问句和字段语义校验。2026H1、2026年营收、预测2027E等是财务/统计期，不能转成报告发布日期范围；明确“某日发布的报告”才产生发布日期条件。机构、公司、类别条件必须有原问句中的依据，不能把IDC等被引用机构当成报告券商。
- 多报告条件遵守report_type分支；不将某个股的security_name作为全局AND条件误排除同问题所需行业/宏观报告，也不推断性地丢掉其中一家公司的名称。
- 可靠、明确的自然语言报告范围作为已确认约束，不因空召回自动丢弃。不可靠、无法验证的自动条件仅作为提示，不能作为唯一硬排除依据。
- 兜底仅撤掉未经确认的自动候选，最多增加两次过滤计划尝试；保留显式API和已确认范围。没有可放宽条件时，原范围内dense兜底维持原限制；仍无结果则报告真正的空召回。基础设施故障不启动放宽。
- 每次尝试保存原条件、有效条件、弃用字段、理由、候选深度和错误；结果来源必须满足显式/已确认约束。兜底结果不能伪装成满足已被忽略的机构/日期范围。

本批不以取消所有过滤、改生成提示词或调整融合权重来规避问题。
